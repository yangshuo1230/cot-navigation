# 选错分支是否因为路径没有训练过？

核查旧N100 PATH测试集中13条走进无用分支的轨迹（简单图9、困难图4）。扫描训练query缓存的全部PATH变体和WALK，不使用val/test样本作训练曝光，也不做新生成。

|检查|简单图9条|困难图4条|
|---|---:|---:|
|存在完整正确训练witness子路径|9|4|
|实际生成的错误整条轨迹也在训练缓存中出现|8|3|
|出错位置的正确下一步在同目标条件下有监督|1|3|
|错误边在其他目标/游走上下文中出现|9|4|

所以不能说这些失败由“没有完整正确训练路径”造成。很多错误输出本身也是熟悉的路径，只是用于当前目标时不对。缓存覆盖不证明真实内部路径检索机制。

“当前节点u，目标t，下一节点v”的正确局部监督比完整witness出现更强。完整witness可能只是其他目标训练样本中的子路径，或来自负查询的随机路径，故并不代表模型在相同目标t下被教过当前分支选择。简单图8/9、困难图1/4没有该正确同目标局部监督。

困难图V236→V65的失败输出V236→V93→V89→V225，在训练缓存中确实出现过，来自目标V225的正例路径（可为其连续子路径）；对V225有用，对V65则第一步就错误。这个位置没有相同目标V65的下一步监督，但正确的V236→V65完整witness已在其他训练上下文出现。

另一方面，困难图V147→V55在V91处本应直接走V55，这个同目标正确选择在10条缓存变体中出现过，模型仍选V16；V247→V55在起点应选V112，同目标正确选择出现于8条缓存变体，模型仍选V104。因此不能把所有失败归为未见目标条件组合。

这些计数都是可采样训练缓存的覆盖，不是优化器实际曝光次数；例如“10条变体”不等于训练10次。错误选择从未作为相同目标下的监督出现，符合有效路径数据语义；它在其他上下文出现才是本次要检查的混淆来源。

完整逐查询记录与匹配训练query/variant、训练目标、正确witness在simple.json与hard.json。run.py只读CPU复现，没有新训练或数据缓存修改。
