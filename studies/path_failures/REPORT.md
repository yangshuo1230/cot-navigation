# 旧 N100 PATH 的失败方式

结论：失败主要是分支选择和停止/答案判断出错，不是输出不存在的边。困难图4个错误全部为选中合法但无法到目标的分支，继续走到汇节点后答NO；简单图另有到达目标后继续走、未到目标却答YES的情况。

## 口径

- 沿用刚才完整witness暴露审计的旧N100简单/困难固定图PATH验证best，不是新N160限制暴露模型。
- 直接审计原测试集保存的完整自由生成，不重新生成、不在首错时截断。真实图检查每条边与任意节点到目标的可达性。
- 正例要求完整合法路径结束于目标，负例按训练协议要求合法路径走至汇节点；答案另与真值比较。负例走到某个汇点不是不可达证明。
- 主错误类型互斥：到达目标后继续走优先列为停止错误，非边属性另存；本次所有失败轨迹的边均真实合法，无预算截断或被审计器中止。

## 解释

在有向图上首次从仍能到目标的节点进入不能到目标的后继后，继续沿边前进不可能恢复成功；这些PATH输出没有回溯再选别的分支，而是继续走后给出NO。行为上符合把当前路径失败当作不可达结论，不能据此认定其内部具体实现了何种匹配算法。
简单图的过目标案例说明终止条件本身也会失败：例如V211→V164已输出V211→V43→V165→V164，却继续走到V140并答NO。
简单图V85→V159则走进V147分支，未见目标，最后仍答YES；因此答案正确并不保证路径正确，最终答案也不是所有样本上都严格遵循末节点等于目标的规则。
此前严格无训练完整witness的15+6个查询全部成功，本次失败查询均在已有训练完整witness的其余测试集合中；缓存有路径也不保证模型一定取到或在正确位置停下。

simple.json/hard.json保留原始checkpoint标识、每条失败的真实边合法性、首个无用分支、有用后继、目标出现及停止状态。CPU只读分析，无模型前向、训练或新checkpoint。
