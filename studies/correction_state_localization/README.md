# 60%纠错模型的搜索状态定位

仅使用l6/l9 p60 s0/s1的latest200k；冻结导航模型，不训练或保存新模型权重，禁用W&B。
使用N100简单新图的正样本。默认等待GPU0空闲；用户已授权本轮共用GPU0。
使用--share-gpu时只要求剩余显存至少24GiB，并将本进程PyTorch显存池限制在20%（80GB卡约16GB）。
共享会争用算力；不会停止已有任务。

自然生成1536 train、256 val、256 test个官方划分查询；全部图/query隔离。
train/val最多生成前4条动作记录，test最多16条，遇首错或MISTAKE提前停止。
只取整条记录正确且此前无错的记录；不以最终答案筛选样本，不修补轨迹。
采样位置为四字段各自的entry/end（未输入该字段第一个token/关闭符之前）。
early=动作1–4；later=动作5–16。后者是仍然正确的自然前缀，存在幸存者偏差。

字段分类跨四字段训练，其他探针逐字段、entry/end、逐层独立线性训练，无层间权重共享。
变量：动作序号与栈深度（回归，四舍五入准确率和MAE），栈/visited/有边后继/
有边未访问后继（256维成员关系），栈顶与从栈顶起前8槽的节点身份。
栈成员探针不代表顺序恢复；深度超8时槽位探针不覆盖完整栈。
集合指标仅在图内节点上统计，固定0.5阈值，报告普通/平衡准确率、正类recall、
precision、整集合精确匹配；节点身份另报完整256词表top1，不用oracle集合大小。
每层加入当前输入token embedding+绝对/CoT位置对照。完整字段读完可直接复述，
必须和entry位置、输入对照一起解释，不能单凭高准确率认定存在算法模块。

探针为独立仿射映射，AdamW lr=.003、wd=.01，3000步，batch256，
每100步逐头按独立验证损失选步，训练统计量标准化。集合BCE按训练类比例加权；
字段为4类CE；序号/深度为MSE。测试不选超参或阈值，不汇报AUROC。

另用原输出头logit lens和独立仿射校准lens，逐层检查自然下一token精确匹配及与
真实最终头的一致率。校准只蒸馏冻结最终logits，不监督正确token；2000步、验证KL选步。
512个训练query/128个验证query单独保留给lens，其余给状态探针，无query重叠。
目标是当前位置的下一token，不是最终YES/NO。正样本单类下最终YES/NO准确率不足以诊断机制。

```bash
.venv/bin/python studies/correction_state_localization/run.py --background --share-gpu
```

输出目录outputs/analysis/correction_state_localization_20261102：状态、日志、计划、
自然短轨迹配方和4个模型的紧凑JSON结果。每完成一个探针即更新结果；不保存activation
或探针权重。各模型自然前缀不同，跨模型比较需要同时看样本覆盖和输入对照。
