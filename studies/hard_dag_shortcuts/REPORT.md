# Fixed DAG：已有 checkpoint 的 shortcut 检测

检测完成，未重新训练。使用 N36、N100 的 Direct / Path 验证集最佳 checkpoint，
在 GPU 0 上重新评测完整测试池，分别为 63、555 条查询。四个模型共 1,236 次自由生成。
使用原生贪心生成、原始 32k 上下文和 batch=16，不通过轨迹合法性修改最终答案评分。
与之前保存的评测交集相比，四个模型的答案预测均无变化。

## 结论

单纯背诵完整 WALK 不足以解释当前表现，Path 在 N100 上也没有出现非边跳转。
但训练 PATH 中的子路径覆盖很强，所以这些结果仍不能证明模型学会了通用搜索算法。
固定图的可达关系记忆、目标条件下的路径检索，以及子路径拼接都仍是合理解释。

## 2. 排除完整 WALK 记忆后的结果

以下各组全部为正例，不能将其当作完整二分类准确率。
WALK 中见过是指该知识语料中存在从查询起点到终点的连续子路径，
不是确认某个具体优化步骤已经用过该条 WALK。

| 图 / 正例分组 | 数量 | Direct 答案正确 | Path 答案正确 |
|---|---:|---:|---:|
| N36：WALK 中见过完整 witness | 35 | 29/35 = 82.9% | 32/35 = 91.4% |
| N36：WALK 中没见过完整 witness | 7 | 7/7 | 7/7 |
| N36：真实最短路径至少 5 跳 | 6 | 6/6 | 6/6 |
| N100：WALK 中见过完整 witness | 100 | 93/100 | 97/100 |
| N100：WALK 中没见过完整 witness | 200 | 196/200 = 98.0% | 199/200 = 99.5% |
| N100：真实最短路径至少 5 跳 | 151 | 149/151 = 98.7% | 151/151 |

WALK 最长只有 4 条边，因此至少 5 跳的完整 witness 不可能出现在单条 WALK 中。
这里的跳数由图上独立最短路径计算得到，没有使用旧的 rank-gap 字段代替。
长跳组表现好不能单独解释为算法泛化：这是同一张固定图，并且这些样本的其他
结构属性可能不同。

## 3. Path 轨迹是否合法

| 检查 | N36 | N100 |
|---|---:|---:|
| 从起点开始、逐边合法、无重复、无非法 token | 63/63 | 555/555 |
| 正例中实际到达目标的合法 witness | 38/42 = 90.5% | 296/300 = 98.7% |
| 正例回答 YES，但没给出有效成功路径 | 1/39 | 0/296 |
| 非边跳转 | 0 | 0 |
| 参考预算中断 / STOP | 0 | 0 |

N36 的一个实例，以内部节点编号表示：

```text
查询：14 是否能到 27
合法成功路径：14 → 24 → 27
模型输出：14 → 24 → 28，YES
```

输出路径的两条边都合法，但没有到目标；最终答案仍然正确。这是一次
答案与显式 witness 不一致，不能因此概括为所有查询都不使用 CoT。

N100 的 4 个正例错误都没有生成成功 witness；没有出现“答案正确却凭非边到达目标”。
负例上的合法随机路径只证明路径局部合法，不是不可达证明。

## 4. 进一步检查训练 PATH 子路径曝光

只排除 WALK 不够。我们逐条扫描了训练查询实际准备的 PATH token 缓存，
包括所有正例合法路径以及负例的随机路径。只扫描 train query ID，不使用
验证或测试路径作为训练曝光。正例缓存覆盖所有合法路径，负例缓存为四种随机路径。

* N36：42/42 个测试正例的某条完整 witness 已作为训练 PATH 的子路径存在。
* N100：294/300 个测试正例的某条完整 witness 已作为训练 PATH 的子路径存在。
* N100 仅剩 6 个正例：WALK 和全部训练 PATH 缓存均不包含其完整 witness。
  Direct 6/6 正确，Path 6/6 正确且均给出合法成功路径。

这是“缓存可提供的监督”检查，不是精确的优化器曝光重放。
Direct 没有收到 PATH 监督；同一分组对 Direct 仅表示共享查询面板，不能说它看过 PATH。

我们还检查了**模型实际生成的那一条路径**，而不是只检查相同起终点是否有其他
路径在训练中出现过：

| 图 | 合法成功输出数 | 实际输出曾是训练 PATH 子路径 | 对 WALK 与训练 PATH 都新的成功输出 |
|---|---:|---:|---:|
| N36 | 38 | 38 | 0 |
| N100 | 296 | 282 | 14 |

所以 N100 中存在新的整段路径输出，但大部分成功输出在训练缓存中可以找到。
这 14 条新路径包含上面的 6 个严格未见 witness 查询。样本很少，且可能由熟悉的
短片段拼接产生，因此支持一定的组合行为，尚不能排除固定图上的关系记忆。

一个严格未见 witness 的成功例子，仍使用内部节点编号：

```text
查询：39 → 78
模型输出：39 → 50 → 70 → 72 → 74 → 75 → 78，YES
```

每条边合法，实际到达目标；没有完整训练 witness 不意味着这些单条边没有被学习。

## 5. 简单统计对照

只用训练查询拟合计数表：分别按起点 ID、终点 ID、两端入出度分组，
用训练标签频率预测测试标签。没有使用测试标签选择规则，也没有使用测试
最短路径或拓扑排名作为预测输入。两端度数是从真实图读取的诊断特征。

N100 整体准确率：起点 ID 70.6%，终点 ID 73.3%，两端度数 69.2%；
对应 balanced accuracy 为 69.7%、72.5%、69.2%。
这些具体的简单规则不足以达到 Direct 的 97.5%，但没有穷尽所有统计 shortcut。

## 解释边界与下一步

目前能排除“只要背完整 WALK 就解释了全部高分”，也没有观察到 N100 Path
通过非边跳转制造成功 witness。我们尚未区分参数中的可达关系表、路径记忆与
可泛化的搜索算法，也没有做路径输入的因果干预。

已有测试集中严格未见 witness 的正例只有 6 条，单靠重分组无法构造有力的
组合泛化基准。下一步适合做跨块 query 留出，并在数据准备时显式约束 WALK
和任务 CoT 的完整 witness 曝光；保留边知识覆盖，同时避免长段测试路径直接
成为训练监督的子路径。
