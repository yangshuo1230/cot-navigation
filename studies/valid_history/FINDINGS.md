# 本轮结论

按用户确认的两个方案执行：完整重放 CoT；构造合法历史配对。没有重做跨图迁移。
沿用上一轮验证集选出的 60 个 checkpoint 和相同测试查询，覆盖新图/固定图、N16/N36/N64/N100/课程学习、6 种协议。
显式状态的 DFS/BFS 共 20 个模型另外做历史配对。此次 scale 选择列表中没有 Filler checkpoint。

## 完整重放

逐条检查当前栈/队列、visited、候选集合、PUSH 的真实边合法性、状态更新、终止条件。
允许合法的不同邻居优先级，VIS/CAND 按集合检查，单独记录与展示优先级不一致的 PUSH。
节点版本按展开次序检查；相邻输出节点不相邻本身不算错误。

以下是原有固定图 N100 模型，每格 128 条测试查询，**不是新增三跳训练的结果**：

| 设置 | 答案正确 | 答案正确且轨迹完整合法 | 含非边 PUSH 的查询 | 含栈/队列跳跃的查询 | STOP |
|---|---:|---:|---:|---:|---:|
| DFS state | 126/128 | 112/128 | 2/128 | 5/128 | 9/128 |
| BFS state | 127/128 | 111/128 | 0/128 | 1/128 | 14/128 |

非边 PUSH、状态跳跃是对所有可解析记录的局部检查，可能发生在先前错误之后；不能将它们解释为独立合法历史下的决策。
STOP 只说明轨迹未完整执行，不能一律视为算法错误。DFS 有 16 条查询在重放时检测到具体语义错误；BFS 有 4 条。
其中错误与 STOP 可以同时出现。

新图 N100 的 DFS state：答案正确 94/128，但完整合法且答对只有 37/128；85/128 查询出现局部非边 PUSH，首个错误均为候选集合不符。
这更直接地显示生成轨迹中的图关系检索/候选生成存在问题；不能据此单独断言某个内部模块“相信不存在的边”。
新图课程学习 DFS/BFS 的答案均为 106/128，完整合法且答对分别只有 63/128 和 53/128。

## 合法历史配对

对同一图、同一查询，用 64 种确定随机种子的邻居顺序生成真实执行历史。截在当前 VIS 字段之后、CAND 之前。
所有前缀都由另一套 token 级语义判定器验证合法。每个查询至多取一对，最多 40 对，选样不看模型输出。

DFS 主对照保持完整栈和当前节点相同，在 A 中某后继未访问，在 B 中该后继已经合法访问；尽量匹配 VIS 数量和前缀长度。
固定图 N100 的 40 对中，37 对前缀等长。两侧候选集合和动作全部正确；焦点节点在 A 中 40/40 被列出，在 B 中 0/40 被列出。
焦点作为下一 token 的概率平均下降 0.745，查询对 bootstrap 95% 区间为 [0.627, 0.856]；该概率也受候选输出顺序影响，完整候选集合更容易解释。

一个真实例子，query 1442：两侧栈完全一致，当前节点均为 V204，前缀等长。A 的候选为 {V128,V65}，B 的候选为 {V128}；
B 的合法历史已经访问 V65。模型分别生成 `V128 V65 | PUSH V128 ;` 和 `V128 | PUSH V128 ;`。
历史和 VIS 都随之改变，所以这说明模型会根据合法状态使用 visited 信息，不能归因到单个 token 或某个特定内部表示。

BFS 在这一分层 DAG 家族中无法找到相同完整队列但候选不同的配对；使用了当前节点、队列长度、VIS 数量相同的放宽配对，队列内容会变化。
固定图 N100 中，两侧候选集合正确率为 97.5% / 100%，焦点被列出的比例为 100% / 0%；**不能将效果仅归因于 VIS**。
另有相同 frontier、相同 visited 集合、不同合法历史的控制组，完整数值见 REPORT.md。

这些结果不支持“模型完全不使用 visited、只会回放一条固定 CoT”的强说法，也没有排除记忆常见状态转换、局部查表等 shortcut。
模型在给定正确历史时会局部过滤候选，与自由生成时能否长期维持合法历史，是两个不同的问题。
