# 用真实轨迹解释 DFS 的读取路线

以下均为同一批冻结 checkpoint 的 FP32 检查。前缀是给定的正确参考轨迹；所讨论位置的下一 token 已核对模型 argmax。不是说整条参考轨迹由模型自由生成。Vn 是图内节点编号；`V2@104` 表示位置104输入了V2。位置从0开始。

最重要的区别：在位置q的attention计算中，模型已经读到了token q，用该处隐藏状态预测token q+1。Attention读取的是历史位置的上下文化向量，不只是该处的字面token。

## 1. In-Context：读两个字面相同的V2位置，分别输出V5和V9

模型：简单图课程学习DFS state，best185k。查询50512：V2→V6。

记录格式为 `stack | visited | candidates | action ;`。

```text
第3条：V2 V5 V9     | V2 V5 V9     | V15 V12 | PUSH V15 ;
第4条：V2 V5 V9 V15 | V2 V5 V9 V15 |         | POP ;
第5条：V2 V5 V9     | V2 V5 V9 V15 | V12     | PUSH V12 ;
```

第4条POP后，重写第5条栈时，需要保留V5和V9。原始位置如下：

```text
第3条开头：V2@100 V5@101 V9@102 |@103 V2@104 ...
第4条开头：V2@114 V5@115 V9@116 V15@117 |@118 V2@119 ...
第5条开头：V2@127 V5@128 V9@129 |@130 ...
```

先观察两个历史位置的早层计算：

- 位置104的字面token是第一枚visited节点V2；L1以0.985读取同记录栈中的V5@101。
- 位置119的字面token也是V2；L1以0.997读取同记录栈中的V9@116。

然后看第5条栈如何逐token续写：

- 输入V2@127后，要预测位置128。L5以0.993读取历史V2@104；实际下一输出是V5。
- 再输入V5@128后，要预测位置129。L5以0.993读取另一个历史V2@119；实际下一输出是V9。

所以，字面都为V2的两个位置，不具有相同的隐藏表示：它们经历了不同的上下文读取。模型后续按位置检索，可以得到不同的信息。可将它理解为一种历史表示复用的候选机制；不能仅凭注意力证明“V2@104只存V5、V2@119只存V9”，或证明这些连线构成了必要的因果通路。

一个额外的细节：V2@104当时本来就在预测visited中的下一个V5，V2@119当时本来就在预测visited中的下一个V5。是否能将各层的读取解释为专门的栈寄存器，仍需拆分注意力层和输出计算；不能根据单条连接赋予模型有意设计的存储目的。

## 2. Fixed：类似的POP后，直接强读字面V74的位置

模型：simple fixed all_hops DFS state，best40k。查询151：V65→V87。

```text
第3条：V65 V74 V82     | V65 V74 V82     | V96 | PUSH V96 ;
第4条：V65 V74 V82 V96 | V65 V74 V82 V96 |     | POP ;
第5条：V65 V74 V82     | V65 V74 V82 V96 |     | POP ;
```

对应的栈位置：

```text
第3条：V65@30 V74@31 V82@32 ...
第4条：V65@43 V74@44 V82@45 V96@46 ...
第5条：V65@56 V74@57 V82@58 ...
```

当模型刚读到V65@56、要输出V74@57时：

- L6对上一条栈的V74@44注意力为0.778。
- L6对再前一条栈的V74@31注意力为0.202。
- 对更早所有字面V74位置的质量合计0.994。
- 模型实际输出V74。

这与上例的读取位置选择不同：In-Context强读字面V2的中介位置再输出V5；Fixed此例强读字面V74的位置再输出V74。两者仍都需要根据当前上下文决定读哪个历史位置，并不是看见同名token就自动知道何时输出它。Attention观察也不能证明V74方向没有经过编码转换。

同一查询较早的visited续写也能看到跨字段读取：输入V65@34、下一输出V74时，L6对第一条候选列表里的V74@9为0.646，对第二条visited里的V74@20为0.350。不能把Fixed的路线简化成“只复制上一条visited”；候选、栈等历史字段也可能被读取。

## 3. PUSH为何先关注第二候选，再输出第一候选

查询50520：V11→V14。

```text
第1条：V11     | V11     | V13 V15 V14 | PUSH V13 ;
第2条：V11 V13 | V11 V13 |             | POP ;
第3条：V11     | V11 V13 | V15 V14     | PUSH V15 ;
```

第1条候选与动作的位置：

```text
V13@80 V15@81 V14@82 |@83 PUSH@84 V13@85 ;@86
```

输入PUSH@84后，下一输出是V13；但L1主要读取第二候选V15@81，质量0.947。L4同时读取第一候选V13，L5强读最后候选V14。单独一个层的最大attention不等于最终选择。

探索完V13并POP回来后，第3条前缀是：

```text
V11@96 |@97 V11@98 V13@99 |@100
```

此时应该输出下一个候选V15，模型实际也输出V15@101：

- L5读取旧PUSH@84，质量0.835；同时读取其参数V13@85，质量0.152。
- L6还直接读取旧候选V15@81，质量0.528。

可观察到的关系是：旧PUSH位置早层读取了V15，后续生成下一份候选时又读取旧PUSH；同时还存在直接读取旧V15的路径。这符合复用旧候选/操作表示的解释，但没有证明“PUSH里已经规划好了下一次选择”，也不能声称只有其中一条路线发挥作用。

![候选具体例子](concrete_03_candidates.png)

三个例子足以展示“读取哪个位置”的差别；若要确认“信息到底沿哪条路线传递、哪些内容不可替代”，还需在这些具体位置进行V内容替换或路径消融。完整原始记录保存在concrete_examples.json，注意力数字来自此前独立验证的measure.py结果。
