# 人工注错后的自主恢复与错误探针（2026-10-24）

比较此前同一对普通图训练的 DFS checkpoint：baseline 与 natural-correction p30、轨迹权重16，均为200k步、4K上下文。困难 DAG 是迁移评估，未换成困难图训练 baseline。模型冻结，仅探针在物理 GPU0 训练；未产生模型 checkpoint、激活缓存或 W&B run。

## 设计与验证

每个任务使用96个不同查询，一半可达、一半不可达。每类错误16个查询：候选替换为图内非邻居、候选替换为已访问邻居、候选重复、候选遗漏、visited 混入未访问节点、visited 重复。visited 注错保留起点和当前节点。对同一个合法 DFS 前缀构建正确/错误两版，两模型收到相同输入。输入停在当前状态的最后一个 `|`，不提供动作或修复指令，模型自行生成后续，包括是否输出 MISTAKE。

注错前的完整参考轨迹经过参考轨迹审计；另外每类每任务5个样本用独立语义 oracle 检查：正确前缀无错，注错前缀首次错误恰好在探测锚点。模型、行为测试与探针样本配对通过事件 SHA256 核对。行为注错前缀不超过2048 token，使用模型原生4K剩余预算；仍有后续超长，未删除失败案例。

探针有两个读出位置：(1)刚读入错误 token、下一 token 尚未生成；遗漏错误读出过早闭合的 `|`；(2)完整状态最后一个 `|`、动作尚未生成，检测本条状态前面是否有错。第二处正确/错误输入的最后一个 token 相同。二者都没有未来 token 信息。

探针从最后3层读取 residual activation，比较线性和64宽 GELU MLP。普通图、困难图各有8192训练对、2048验证对、4096测试对；窄深图4096测试对，仅迁移。每对含正确/错误两条，图/查询跨 train/val/test 不重叠，同一查询可以有多类注错。3次探针初始化，1000训练步，按验证 BCE 选择。对照为 token embedding+位置特征，以及加入上一位置预测当前观测 token 的 NLL、熵、与最优 token 概率差的生成概率对照。后者不输入真实错误标签或 oracle。

## 自主续写结果

以下均为 /96。这里不是从图输入开始的完整基准测试，而是正确历史条件下的续写。

|任务|baseline 未注错/注错后答对|纠错模型 未注错/注错后答对|baseline/纠错模型后续首条有效记录正确|纠错模型 MISTAKE 后正确重写|
|---|---|---|---|---|
|普通图 N100|89 / 81|93 / 90|59 / 67|6|
|窄深图 N100|70 / 68|80 / 74|39 / 49|6|
|困难 DAG N100|80 / 79|90 / 87|54 / 66|11|

“后续首条有效记录正确”跳过 MISTAKE 取消记录，检查真实搜索状态的字段与动作，但允许模型先执行被注错记录的合法动作，因此不等于修复了注入字段。真正显式修复要求注错记录主动输出 MISTAKE，且随后首条非取消记录正确。baseline 词表没有 MISTAKE，不能从其显式修复为零推断没有错误意识。

纠错模型显式修复的类型分布：普通图6个全为非邻居候选；窄深图5个非邻居、1个重复候选；困难 DAG 10个非邻居、1个重复候选。其余类型本次均没有显式修复。修复当前记录后仍可能后续出错：三任务注错后完整有效执行并答对分别仅4/96、3/96、6/96。

最终答对可与错误轨迹共存。visited 两类注错后下一记录经常恢复正确，但不能据此称作主动检错或回滚修复。注错后的模型间答对差值及查询成对 bootstrap 95%区间：普通图+9.38pp [3.12,16.67]，窄深图+6.25pp [0,13.54]，困难 DAG+8.33pp [1.04,15.62]；不包含导航训练种子不确定性。纠错模型未注错时也较强，本实验不能把全部模型差归因于注错后的修复。

## 探针结果

下表为普通图训练、第6层 MLP、3初始化均值 AUROC；窄深/困难为迁移。

|任务|刚读入错误 baseline / 纠错|动作生成前 baseline / 纠错|
|---|---|---|
|普通图|0.885 / 0.844|0.557 / 0.648|
|窄深图|0.819 / 0.799|0.555 / 0.640|
|困难 DAG|0.851 / 0.807|0.553 / 0.639|

刚读入错误时纠错模型并未全面增强。普通图线性第6层对应0.822/0.741，MLP能进一步解码信息。动作前线性对应0.550/0.622，MLP对应0.557/0.648。

动作前按类型观察最关键：非邻居候选普通图 baseline0.496、纠错0.868；窄深0.501/0.882；困难0.501/0.847。重复候选约0.50→0.60–0.63。已访问候选、visited 两类两模型均约0.50；遗漏候选两模型约0.78–0.82，纠错并不更强。

普通图动作前平均输出：baseline 错误/正确0.510/0.486，纠错0.558/0.443；验证正确样本5%误报阈值下，测试检出率14.0%→23.1%，测试误报率6.9%→6.2%。错误信号仍不足以构成可靠通用检测器。概率是在人工正负均衡数据训练的 probe score，不能解释为自然生成轨迹的真实错误后验概率。迁移时误报率可能改变。

重要负面对照：刚读入错误时，加入生成概率信息的简单对照普通图 AUROC 两模型均约1.000，高于深层 activation 探针；token身份/位置本身约0.50。因此人工错误通常低概率，不能把很高的即时解码率解释为独立的语义自检能力。动作前该对照仍约0.815/0.774，也高于第6层 activation 探针。它预测的是最后观测 token 的惊讶度，不是整条轨迹的 oracle 错误。

## 联合观察与解释边界

在同一批行为事件上，纠错模型真正显式修复的样本，其动作前错误 probe score 均值普通图0.990、窄深0.988、困难0.995；未显式修复样本约0.52–0.53。但修复几乎集中于非邻居类型，这个关联存在错误类型混杂，不能证明探针方向是修复的原因，也不能将模型间差异归因于 attention。

目前证据支持：模型已学会一部分错误类型的检错—重写行为，对应的信息能够在动作生成前被解码；不支持一般性的“模型知道所有 CoT 错误并能纠正”。后续应优先补充已访问候选和 visited 的错误监督，以及检错信号到 MISTAKE 动作之间的因果干预，并用更接近自然错误概率的注错对照检查捷径。

## 文件与复现

- `repair_{main,deep,hard}_{clean,error}.json`：6份行为结果，各96对。
- `probe_{clean,error}.json`：探针指标、事件哈希及少量实例，无激活或探针权重。
- `summary.json`：汇总及成对 bootstrap 区间。
- `injected_error_behavior.png/.svg`、`injected_error_probe.png/.svg`：关键图。
- 上一级 `injected_error_common.py`、`injected_error_repair.py`、`injected_error_probe.py` 为服务器分析入口；`summarize_injected_errors.py` 本地汇总绘图，可重复运行。
